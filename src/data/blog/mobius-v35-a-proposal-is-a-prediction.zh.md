`ActionIntent.expected` 写在派发**之前**：一句描述、一组机器可判定的断言、一个 `reversible` 标记。
`VerificationResult` 写在**之后**，为其中每一条断言带回一个结果。两半从 V18 起就在 journal 里。

**从来没有任何东西把它们当作一对来读。**

这就是 V35 的全部。不是预测器——是**给运行时已经在做的那些预测打分的东西**。因为在它存在之前，
根本没法回答「加一层预测到底带不带信息」，而一个把置信度往上吹的变异，也没有任何东西能杀死它。

### 为什么打分器排在预测器前面

文献扫下来，没有一个运行时闭上这个环。FOREAGENT 用模型自报的置信度做门控，离线拿静态语料做校准，
循环内从不重新打分。BCO 会给一份 `prediction.md` 打分，但靠的是 LLM 判断——没有 proper score，
也没有世界版本。CASE 是语料里唯一一个在线、可结算、经过校准的概率，可它的对象是运行时内部量
（「猜测的输入会不会命中」），而不是关于世界的断言。State-Aware Runtime 把这条义务写了出来，
没有实现。

所以这个顺序是有意的。同样有意的，是这一版拒绝成为的三件事：

**不是生产者。** 没有新事件类型、没有模型调用、没有新 port。`loop.ts` 一行没动——它一旦动了，
这就不再是对「运行时本来就在做什么」的测量了。

**不是门控的输入。** *校准不是控制。* 重校准能把校准误差压到接近零，而控制上的 regret 纹丝不动；
与控制真正相关的量是 action-conditioned advantage，那需要这个运行时还没有的分支反事实。
这张表说的是提议者预测得准不准。它不决定任何事。

**不是置信度。** `expected.assertions` 今天不带概率，V35 也不加。现在能数的是
**离散预测对离散结果**，也就是 precision 和 recall，不是 Brier。概率字段值得加，
但要等这张离散的表被证明不是退化的之后。

### 写在代码之前的那条「死刑条件」

预测照例先写下来，而第一条就是给整个想法留的死法：

> **P1** —— 在真实模型的录音上，至少有一条断言结算为 `violated` 或 `undecidable`。
> **如果真实提议者写过的每一条断言都被满足，这张表就没有信息，主论点里预测那一半在这里就死了。**

它成立了，而且不勉强。一条提议者的断言写着 `"retryLimit": 5`，而字节里是 `9`：
`fs.write` 的精确率 `0/1`。这张表量的不是一个只会说对的提议者。

**P2** 更有意思。一个 intent 声称 `reversible: true`，而它编译出来的动作路由到了 `fs.delete`，
后者的 manifest 写着 `irreversible-write`。那份日志里**根本没有任何 authority 事件**——
目标不带信封，所以没有东西拒绝它。一次超额声明，被记录下来，而运行时里没有别的东西能说出这件事。

**P4** 是这个项目反复回到的那个形状：派发了却没有裁决的动作是 `ungraded`，绝不是 `violated`。
*预测不可得，不等于预测错了。* `assertionPrecision` 返回 `undefined` 而不是满分——
一次对空集的测量，在最容易顺手报出 `1/1` 的那个地方被拒绝了。

### 值得留下的发现

五个变异里四个变红。第五个才是有意思的那个。

**一个不可能存在的变异。** P5(c) 预测：把 `reversible` 从 intent 读、而不是从编译后的动作读，
会改变答案——前提是这两个是不同的事实。它们不是：编译器原样设置 `expected: intent.expected`，
所以 intent 的声明和编译后动作的声明**是同一个对象**。没有任何行为测试能区分它们。

编译器真正从 manifest 盖上去的是 `semanticEffect`，它自己的注释写着：*「绝不从 intent 来。
Authority 判断的是一个与执行相邻的事实，而不是提议者对自己意图的陈述。」*
所以关于可逆性、由运行时拥有的那个事实**根本不在动作上**——它是能力的 effect class，在 manifest 里。
这正是打分器把 `effectClassFor` 作为参数接进来的原因：**journal 不携带被检查的那个事实**，
一个从能力 id 推导它的投影器就是在发明它。顶替 (c) 的那个变异——*相信这个声明*——变红了，
而它是同一个问题的诚实形式。

**一个红不了的 pin，被它自己的电池抓住。** P2 的第一版断言门放行了一切：

```ts
expect(rulings).not.toContain('authority.refused')
expect(rulings).not.toContain('authority.escalated')
```

一个对照变异——换成一个从不出现的字符串——**活了下来**。这两条断言对任何**因为任何原因**
没有发出 authority 事件的 run 都成立，包括压根没走到门那里的。这个文件在被写来测量别的东西时，
自己长出了一个死 pin。

修的是量具而不是断言：同样的删除、同样的超额声明，但对着一个信封写着 `otherwise: 'approve'` 的目标。
现在 `authority.escalated` **确实**在日志里，什么都没派发，而表里没有记录任何声明——
它只能给运行时真正做过的事打分。第六个变异把那个信封削弱掉，对照就变红，
所以这个对照本身也是承重的。

**一个编译不过的绿色套件。** 七个测试通过，而同一个文件里立着三个类型错误——vitest 转译但不查类型。
电池的基线打印出*「树上已有 3 个类型错误；只算新增的」*，正是编译守卫在做它被造出来要做的事，
而且是在这个「专门用来测量预测」的版本上。

**一个被点名而不是被折进总数的数字。** 这里有十六个套件要绑 Unix domain socket，
而这个环境以 `EPERM` 拒绝。没有假设这与本版无关，而是在一个干净的 worktree、
在 `HEAD` 上、在本版任何文件都不存在的情况下复现了同一个失败——同样的消息，1.83 秒对 1.82 秒。
所以这一版能诚实声称的是 `147 files · 1381 passed | 1 skipped`，
把排除项说出来，而不是藏进一个总数里。

### 还剩什么

- **没有概率，所以没有 proper score。** 这里量的是离散预测的精确率和召回率。加概率会改动一个协议类型、
  也会改变对提议者的要求——只有在这张离散的表被证明不退化之后才值得做。
- **没有任何东西消费这张表**，这是设计。下一个问题不是「把它接进门」，而是这个残差到底有没有决策价值，
  而那需要先有概率字段。
- **`effectClassFor` 是参数，不是投影。** 调用方可以传进一份与运行时实际路由时所用的目录不一致的目录。
  今天没有东西强制它们一致。
- **只有一个能力族。** 这里每个用例都是文件系统。
- **预测上没有世界版本。** 一个在预测与裁决之间发生了变化的世界，现在被算成一次失手，而不是作废。
  那是下一版的第一个问题，它决定这张表量的是提议者还是天气。

### 那唯一一个正确的红

`tests/publication-claims.test.ts` 是红的：

> `V35 has a plan and no post: add a row to PUBLICATION.md`

这是规则在生效，在它被写下之后一个提交。代码是绿的，电池是干净的，而这一版**没有完成**——
因为一个版本完成于它被发布，而不是完成于它变绿。那一行要写出 slug、活的 URL 和日期；
在文章存在之前先写下它，就是发明一条记录，而这正是这个仓库已经抓住自己五次的那种失败。

你正在读的，就是把它关掉的那个东西。

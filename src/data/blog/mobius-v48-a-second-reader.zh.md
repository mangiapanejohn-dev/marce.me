V47 收尾时定位了独立证据的障碍：不是缺一个 emitter，而是缺一个**第二来源**——另一个对同一个事实持
有意见的读取者。它点了最近的那个：`repo` 和 `filesystem` 都能看见同一棵工作树。

这一版去把它量了。它确实在，但形状不是那句话让人以为的那个。

### 显而易见的那个第二证人并不存在

自然的做法是比对逐路径的内容摘要：filesystem provider 报 `{path, digest}`，那就问 repo provider 要
同一个路径的同一个东西。

它不报这个。`PathChange` 带的是 `{path, index, worktree, renamedFrom, conflicted}`。仓库知道一个路径
**变了**，从来不知道**变成了什么**。两个 provider 从来不在同一个粒度上陈述同一个事实——所以你在白板
上会画出来的那种互证，在任何代价下都不可得。

仓库真正带着的，是两个覆盖整棵树的 token：`diffDigest`（被跟踪内容）和 `changeSetDigest`（哪些路径
处在哪种状态）。

### 三个证人，有用的部分在于它们盲在哪

把两个 provider 都挂到同一棵 git 树上，走四步：

| 步骤 | fs 摘要 | `diffDigest` | `changeSetDigest` |
|---|---|---|---|
| 基线 | `2c8b08…` | `e3b0c4…` | `6be11…` |
| 编辑被跟踪文件 | `27dd8e…` 动了 | `06d723…` 动了 | `1ce41…` 动了 |
| 再编辑一次 | `f69369…` 动了 | `3c7ef7…` 动了 | `1ce41…` **没动** |
| 新建未跟踪文件 | — | `3c7ef7…` **没动** | `59e80…` 动了 |

第二行就是互证：一个文件系统摘要和一个仓库 diff 摘要，不同的进程、不同的算法——`stat` 完再哈希字节，
对比把 `git diff` 的输出做摘要——对同一个文件达成一致。这是这个 runtime 里第一次，一个主张有两个证人，
而不是一个被带下来的。

第三、四行才是这次测量值得做的原因。每个盲区各自都被写过；表格加进来的是它们**互不重叠**。已经改过的
文件再改一次，会动内容 token，不动状态 token。未跟踪文件反过来。谁都推不出谁——而一个只编辑一次被跟踪
文件的测试，会看着三个一起动，然后得出结论说这是同一个测量做了三遍。

### 它实际能裁决什么

V47 量过这个 runtime 唯一一个悬着的分歧：在 `worldRevision` 相等时，receipt 的摘要和验证观测的摘要
不一样，而 V37 把它读作*世界动了*，而不是*两次读取里有一次是错的*。runtime 里没有任何东西能分辨这两者。

`diffDigest` 能，对被跟踪的文件而言。它也动了，那就是世界动了；它没动，那就是没动。这是这个项目里
第一个第二来源真的能裁决的主张。

也值得把这种独立性说准。两个读取者读的是同一块磁盘、经过同一个内核的同一批字节。一个损坏的文件会让
两个摘要以完全相同的方式损坏。这里的独立是**实现**的独立，不是**来源**的独立——它抓的是读取者的错，
不是世界的错——这一点被钉成了一条限制，免得这份互证被读成比它实际更多的东西。

### 为什么没在它上面建东西

用它，就意味着 runtime 要取一次 `repo.status` 观测去裁决一个文件系统的裁决：验证路径内部的一次跨
provider 读取。有三件事让它成为独立的一版。

它**要花一次 look**——一次被门控、被预算的观测，而这条路径 V44 和 V45 花了两版把它变**便宜**。它
**只对被跟踪的文件有答案**，而 V37 最在意的那种情况是 runtime 刚刚创建的文件，恰恰是 `diffDigest`
瞎掉的地方：证人最弱的地方，正是问题最响的地方。而且它**需要两个 provider 在同一次 run 里**，所以
它先是一个组合层的改动，才是一个 runtime 的改动——而组合层正是 V40 伸手进一个它没考虑过的平面时
翻车的地方。

所以对 V48 诚实的读法是：H5 从*够不着*，变成了*够得着，而且可能不值得去够*。这是一种进展，而这条线
早期的几个版本会很想把它写成一个 feature。

### Battery 里的两条记录

没有生产代码改动，所以三条 mutation 攻击的是 pin 所依赖的那些 token。全部被杀。值得点名的是第二条：
把 `changeSetDigest` 变成对内容敏感，会把两个证人塌成一个，而整个发现恰恰是它们**不一样**。那条抹掉
发现的 mutation 被抓住了。

第四条造不出来——用 porcelain 码去过滤未跟踪路径（`c.index !== '?'`）是个类型错误，因为 `ChangeKind`
是一个具名联合（`'untracked'`），不是它被解析自的那些线上码。这是这条线里第五条造不出来的 mutation，
每次原因都一样：照着**接缝**处的形状去写变异，而不是照着**现场**的形状。compile guard 报告了它，而
不是把那次红算成一次击杀。

还有一个测试是被刻意排除的。V43 的规则是*从改动碰到的东西推导清单，也从最近钉住它的东西推导*——但
V47 钉的是**文件系统**那一侧，一行仓库代码都没碰，所以在这里跑它测不到任何东西。这条规则是双向的：
因为出身而不是因为覆盖被塞进清单的测试，是凑数。

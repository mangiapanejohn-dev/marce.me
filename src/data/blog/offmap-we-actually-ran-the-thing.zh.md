在活动真的存在之前写活动系统，有一种很具体的不真实感。

你写完报名流程，没有人报名。你写完审核队列，队列是空的。你写完评审、计分、提交截止、每位选手四票的投票系统，全部拿你自己造的种子数据跑通了——也就是说，全部在一个同样由你写出来的世界里跑通了。有好几个月，对 Offmap-X 最诚实的描述是：一份 Postgres schema、二十多个 server action，加一个构建能变绿的 Vercel 项目。

然后 8 月 23 日，人来了。

### 在人来之前存在的东西

前史我尽量说短：我一开始是给一个没有网站的黑客松做了个网站，做着做着成了那个团队的第一个工程师，后来这件事和这批人各自往前走，变成了自己的东西。Offmap-X 就是那个东西。我是主办团队的 CTO，具体到日常，意思大概是凌晨两点手机响的那个人是我。

到成都站的时候，「那个网站」已经不是一个网站了。报名、认证。选手与队伍管理。管理后台、审核流、评审流、带文件上传的作品提交、投票、票据与报销、事务性邮件、选手签的席位协议。Server actions、API routes、webhooks、行级安全策略、存储策略、存储过程、CI 安全检查。它是一个真正的应用，每一条接缝我都能凭记忆讲出来——而这些东西没有任何一条告诉我，那栋楼里将要发生什么。

### 它不再是软件的那一刻

下面这件事我不认为有别的学法。

预发环境里的一个 bug 是一道题。你复现、缩小、修好，全程房间里只有你一个人。活动现场的一个 bug 是一个站在你面前、提交不上作品的人，时钟是真的，他后面还排着十一个，而修复和对话是同一件事、在同一时刻发生。

有一部分确实是代码。8 月 23 日我在本地预览里发现一条投票路径，界面记 1 票、服务端记 3 票——这种偏差在没人在乎那个数字之前是不可见的，而一旦有人在乎，它就是唯一重要的东西。我还发现一条兜底路径，在迁移窗口里当前赛事解析为 null 时行为不对。有七个数据库迁移的日期落在活动期间：23 号一个，24 号一个，25 号——最后一天——五个。海报格式、单人选手的上传策略、一份作品到底归谁、每队四票。这里面每一条，在有人真的去用它之前，都显得已经定义清楚了。

还有很大一部分根本不是代码。场地只有一个 WiFi 出口。也就是说全场共用一个 IP，而一条朴素的按 IP 限流——最显然的防御，两周前的我会想都不想就写上去——会把整个会场锁在自己的活动外面。签到走摄像头，那么无论还在收紧什么，摄像头都必须一直可用。我们的自动保存每两秒一次，对一个人没问题，对一屋子人就是每分钟上千个请求。我此前在抽象层面做的每一个安全决策，都在房间真的存在之后，多出了一条物理约束。

这一整套我本来就是防御性地建起来的，起因是一周前的一次事故，那件事我另外写了。坐在会场里，是这些防御第一次必须和几十个人挤在同一个网络上、飞快地做合法的事情共存。这不是同一种测试。

### 从开发者到运营者

那三天我并没有一直坐在电脑前。大概一半时间在电脑前，另一半在做我完全没受过训练的事：向一个把规则理解成另一个意思的人解释规则；判断一份晚了四分钟的提交算不算提交；让一屋子人按流程走完展示；把同一个问题回答十一遍，而第十一个人从我语气里听到的东西不能和第一个人不一样。

七十二小时的活动里混乱很多。东西会坏，人会看错说明，作品在投影上渲染不出来，有人的队友走了，日程滑了一次又滑一次。我一直在等自己绷不住的那个点。它基本没来。不是因为我脾气好——我并不——而是当你就是拿着这个东西的人，不稳住的替代方案是看着它停下来，那件事的说服力非常强。

我最没准备好的一点是：「这东西现在正常吗」不再是一个有技术答案的问题。系统全程都是通的。系统通着，和活动在正常运转，不是一回事，而这个区别我事先讲不出来。

### 它办完了

这就是全部的主张，我觉得它比听起来重。

选手到场了。队伍组起来了。项目被做出来、提交、展示。评委真的评了。Demo Day 发生了。分数出来了。然后大家各自回家，官网现在挂着成都站的回顾，指向下一座城市。

我写过的绝大多数软件，从来没有被一屋子站着的人用过。这个被用过了。报名不是一个流程，是一个人拿到座位的方式。提交截止不是一次时间戳比较，是一支队伍停下手的那一刻。我盯了好几个月的可用性曲线，有三天，是一栋装着人的楼。

它不再是一个网站，而成了真实的人正站在里面的基础设施。我想我是在里面和他们待了三天之后，才明白这个区别的分量。

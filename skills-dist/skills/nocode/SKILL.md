# nocode — 去技术化解释

## 触发与参数
- `/nocode`：开启持续模式。
- `/nocode [问题]`：只对该问题去技术化解释一次。

## 规则
- 零代码块、零行内代码。
- 用类比、流程叙述、文字示意讲清机制（「它先去问登机口能不能进，被拒了才去排队」）。
- 必须指代某段代码时，用一句话描述它做什么：「那段负责检查登录的逻辑」。
- 文件名、命令名允许出现，但不展开内容。

## Persistence
触发后每次回复保持此模式，不随多轮对话漂移回默认风格。
直到用户说「stop / 关闭 / 恢复正常」才解除。
可与其它模式叠加；规则冲突时以最后开启者为准。

## 硬规则
- **任务本身是写代码时**，提醒用户 nocode 模式在生效，确认是否临时豁免这一轮。

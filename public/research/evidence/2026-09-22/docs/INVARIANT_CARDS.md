# Invariant Cards — 冻结版 v1

研究负责人：Claude Science · 2026-09-22 · 工作名 **Classical Invariants, Lost at Agent Runtime Boundaries**

**本文件的硬约束**
1. **不含任何 MØBIUS 实现细节。** 每张卡必须能在一个从未见过其源码的黑盒运行时上评估。这是评审可信度的前提——否则「先看到自己系统的 bug，再挑理论解释它」的指责成立。
2. 每张卡只有四段：`前置条件` → `所需运行时状态` → `违反 oracle` → `经典祖先`。
3. **每张卡必须带两个对照**（本设计的载重部分，非可选）：
   - **正对照**：一个刻意做坏的配置，其 oracle **必须**报违反。若不报，探针不敏感，该卡在该运行时上的「无违反」结果**不得计入**。
   - **负对照**：不变式被平凡满足的配置，oracle **必须**不报违反。若报，该卡有假阳性，结果同样不计入。
   理由：本研究的主结论形态是「大量系统在多数卡上失败」或「大量系统在多数卡上通过」，两种结论都可能由探针失灵伪造。

**驱动方式**：全部探针用**脚本化的确定性 stub 模型**（每个框架的 custom-model / fake-LLM 接口），不用真实 API。好处有三：执行可复现、不需第三方凭据、故障注入时点可精确控制。代价：不覆盖模型自身的非确定性，故本研究**不主张**任何关于模型行为的结论。

## 探针族（与卡交叉，每族都是黑盒可施加的外部事件）

| 代号 | 事件 |
|---|---|
| `P-CRASH` | 进程在某个中间点被 SIGKILL |
| `P-RESUME` | 从持久化状态恢复并继续 |
| `P-WAIT` | 在人类审批／外部输入处长时间挂起 |
| `P-FOREIGN` | 第三方在运行期间修改 agent 已读或将写的外部资源 |
| `P-RETRY` | 工具调用超时后被重试，且第一次其实已生效 |
| `P-ACKLOSS` | 工具已执行但其结果／确认丢失 |
| `P-CTXRESET` | 上下文被截断或重置 |
| `P-MULTI` | 两个 agent 实例并发写同一资源 |

## C1 · Stale Decision / Revalidation

**前置条件** 运行时在时刻 `t₀` 读取状态 `s`，据 `s` 作出一个决定（含人类审批），并在 `t₁ > t₀` 才施加外部效果。
**所需运行时状态** 决定所依赖的 `s` 的身份（版本／纪元／摘要），且在施加前可比对。
**违反 oracle** 在 `t₀` 与 `t₁` 之间由第三方把 `s` 改成使该决定不再正当的值；若效果仍被施加且无升级／拒绝／重新决策，则违反。
**经典祖先** 乐观并发控制的后向验证；`If-Match`／ETag 条件写；lease／fencing token。近邻：selective revalidation（区分 version conflict 与 decision conflict）。
**正对照** 把身份比对关掉（或用 `advisory` 语义），oracle 必须报违反。
**负对照** 第三方不做任何修改，oracle 必须不报。
**探针** `P-WAIT` + `P-FOREIGN`。

## C2 · Durable Consumption / Semantic Replay

**前置条件** 运行时消费一个**一次性**额度（授权预算、配额、单次令牌、幂等键），随后崩溃并恢复。
**所需运行时状态** 已消费量必须在恢复边界之外持久，且恢复后从持久值继续。
**违反 oracle** 恢复后同一额度可被再次消费（计数归零、令牌可重用、预算复原），则违反。
**经典祖先** durable execution 的确定性重放要求；exactly-once 语义；幂等消费者。近邻：把恢复后重新消费授权预算明确命名为 semantic replay 的工作。
**正对照** 把额度计数器置为进程内存态，oracle 必须报违反。
**负对照** 不崩溃，顺序消费到耗尽，oracle 必须不报。
**探针** `P-CRASH` + `P-RESUME`。

## C3 · Replay-State Closure

**前置条件** 恢复机制通过重放已记录的步骤来重建状态，而某一步在首次执行时修改了**记录之外**的状态（外部变量、文件、远端资源）。
**所需运行时状态** 所有影响未来控制流或外部可见效果的非确定性结果必须被记录，而非在重放时重新产生。
**违反 oracle** 重放后，某个影响后续控制流的值与首次执行后不同（或被跳过的步骤留下未恢复的副作用），则违反。
**经典祖先** 确定性重放；记录-重放的非确定性封闭性；副作用必须 journal 而非重采样。厂商文档已给出同构反例：step 首次执行修改外部变量、重放时被跳过、该变量回到初值。
**正对照** 让一个步骤把非确定值写进内存而不入日志，oracle 必须报违反。
**负对照** 所有步骤纯函数且无外部副作用，oracle 必须不报。
**探针** `P-CRASH` + `P-RESUME` + `P-ACKLOSS`。

## C4 · Provenance Preservation

**前置条件** 运行时在某一子系统记录了某事实的来源（哪个动作／工具／资源产生了它），而另一子系统的正确性依赖该来源。
**所需运行时状态** 来源必须随事实一起跨越子系统边界，而不是只存在于产生侧。
**违反 oracle** 消费侧在来源不可得时**静默降级**（改用散文解析、模型判断或默认值）并给出与实质结论不可区分的输出，则违反。
**经典祖先** provenance 半环与 why/how-provenance；分布式追踪的 context propagation；审计日志的来源字段。
**正对照** 在边界上把来源字段剥掉，oracle 必须报违反。
**负对照** 消费侧不依赖来源，oracle 必须不报。
**探针** `P-RETRY` + `P-MULTI`。

## C5 · Temporal Evidence Preservation

**前置条件** 一条正确性条件断言的是两个时刻之间的**关系**（由 A 变为 B、改动前的值、其余未变），而运行时的某个效果会使前态不可再观测。
**所需运行时状态** 判定该关系所需的前态必须在该效果提交前被保留，且在判定时可得。
**违反 oracle** 该条件在效果之后变为不可判定，**而所需前态其实存在于运行时记录中**（只是未被送到判定处），则违反。若前态从未被记录，则记为 `NOT-CAPTURED` 而非违反——那是不同的缺陷。
**经典祖先** 过去时线性时序逻辑的过去算子；物化视图的自维护性与 auxiliary views；WAL 的 before-image。
**正对照** 强制判定器只接受每个资源的最新观察，oracle 必须报违反。
**负对照** 条件只约束最终状态，oracle 必须不报。
**探针** `P-FOREIGN`（外因）与无注入的自致覆盖（内因）两版都要跑。

## C6 · Monitorability / Observation Completeness

**前置条件** 运行时对一条正确性条件作出裁决，而该裁决所依据的观察集合由**被裁决的一方**（agent 的动作选择、自述、或其声明的关联）决定。
**所需运行时状态** 裁决所需的观察集合应由**条件本身的指称对象**推导，而非由被裁决方的行为决定。
**违反 oracle** 构造两次执行，其世界最终状态相同、条件真值相同，但 agent 的动作选择不同；若两次裁决不同，则违反（裁决对被裁决方的行为敏感）。
**经典祖先** 运行时验证的 monitorability 及其相对固定观察字母表的可判定性；三值裁决的认知语义；主动监控的规格导向调度。
**正对照** 让裁决只看 agent 自述，oracle 必须报违反。
**负对照** 裁决直接读世界最终状态，oracle 必须不报（若仍报，说明构造的两次执行世界状态并不真的相同，须修构造）。
**探针** 同一任务的两条不同动作路径，无故障注入。

## C7 · Concurrency Isolation

**前置条件** 两个 agent 实例（或一个 agent 与一个外部写者）并发操作同一资源。
**所需运行时状态** 足以判定「我的效果是否被他人干扰」的隔离或冲突检测机制，且冲突必须被暴露而非静默合并／覆盖。
**违反 oracle** 存在一个交错，使两方各自报告成功，而最终世界不满足任一方的条件；或一方的效果被静默覆盖且该方仍报成功，则违反。
**经典祖先** 事务隔离级别与写写冲突检测；向量时钟与因果一致性；多 agent LLM 系统的并发异常层级。
**正对照** 关闭任何锁／条件写，oracle 必须报违反。
**负对照** 两方操作不相交资源，oracle 必须不报。
**探针** `P-MULTI`。

## 预注册的判定规则（写在任何探针运行之前）

**杀死条件（用户原话，逐字保留）**：若在至少 5 个独立 agent runtime 上，预注册的 invariant probes 绝大部分都被正确处理，或者缺陷只在 MØBIUS 出现，则「systematic under-adoption」主张退役。

**支持条件（同样预注册）**：
- ≥3 个独立 runtime
- ≥3 个不同经典理论族（即 ≥3 张不同的卡）
- 同一种「信息存在但跨 subsystem projection 后不可用」的结构
- 可重复触发真实 semantic failure
- 修复通常只需少量 glue／state plumbing，而不是新算法

**报告规范**：每张卡 × 每个 runtime 报告 `{violated, not-violated, NOT-CAPTURED, probe-insensitive, inapplicable}` 五态，而非二值。`probe-insensitive`（正对照未报违反）与 `inapplicable`（该 runtime 无对应机制）必须单独计数，不得并入 `not-violated`——否则「系统通过」与「探针失灵」无法区分。附 drops manifest：多少次探针运行失败、报错或被跳过。

**MØBIUS 的地位**：**不是研究对象，而是第 N+1 个被打的系统**，且在 taxonomy 冻结之后才纳入。它在本研究中的唯一特殊之处是我有它的源码，可用于解释机制——但**任何卡的判定都不得依赖源码**。

## 先验工作的定位约束（必须写进论文）

`OBS` **方法论不是新的**：「预注册不变式 + 黑盒 + 在 N 个独立系统上构造违反执行」正是 Jepsen 及其学术化（Elle，从实验观察推断隔离异常）所做的事。本研究的新意只能在**不变式集合的选择**与**发现**上，不在方法论上。论文须显式承认这一点并引用。
`OBS` arXiv 检索（10 组检索式）未发现 agent runtime 的 Jepsen 类工作；但 Jepsen/Elle、TaxDC、以及「简单测试可预防多数严重故障」一类经典文献**不在 arXiv**（VLDB／ASPLOS／OSDI），故该检索**不构成缺席证据**。定稿前须在 DBLP／ACM DL 上补检，并标注结果。
